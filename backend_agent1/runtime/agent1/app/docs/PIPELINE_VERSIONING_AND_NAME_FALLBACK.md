# 文献抽取、组分库与名称补充的最终流程

## 结论先行

一篇文献只允许一个独立的持续模型会话。会话内可以有多次工具调用和有限的格式修正，但不会把每次 `upsert` 或 `review` 当成正式版本。正式版本只在当前候选通过 `finalize → finish → host publish` 后产生；发布后由内容哈希命名，不能覆盖。

当前的 `NAME_NOT_IN_LOCAL_SCOPE` 是本地词典覆盖提示，不是 OPSIN 失败结论。处理顺序是：保存文献原写法 → 保存同文定义的全名/同义词 → 对主名称做真实 OPSIN → 主查询失败时只对来源声明的原名和别名做有界补充 OPSIN → 若有有限结构图，用 RDKit/Kernel 比较图 → 将“解析成功”“图一致”“模型采用”“优选 IUPAC/PIN”“真实材料身份”分别记录。

### 名称字段的两层语义（当前修订）

`most_likely_name` 是当前可用的名称候选，必须带依据、适用范围、理由、假设和未知；它可以是来源型名称、结构型名称或有边界的材料表达。当前没有独立 PIN/优选 IUPAC 认证通道，因此阅读器隐藏 `preferred_iupac_name` 等兼容字段，并明确显示“当前能力未提供”；封存回读 API 仍保留原始字段以保证历史重放，但不能用它表示名称是否已经认证。以后真正接入独立认证流程时，再单独发布认证字段和回执。历史封存 bundle 不改写，因此“全部 preferred_iupac_name 为 null”不会再被解释成“没有名称候选”。

## 一篇文献的状态和版本边界

### 1. 来源冻结

宿主先校验来源 SHA-256、页数和页图，建立本任务的 `source-index.json`。OCR 已验证时保存 OCR 原始回执；没有可靠 OCR 时直接渲染原 PDF 页图，辅助文本不替代图像。历史答案、人工 JSON、其他文献和旧候选不能进入本篇 solver。

### 2. 建立工作候选

`current.json` 是唯一工作状态，保存材料、图、观察、关系、未知、假设、来源引用和工具回执。模型可多次调用 `upsert`、`check_structure`、`observe`、`prepare_component`、`resolve`、`review_naming` 等工具。这个阶段的写盘不是正式版本；出错可在同一 session 内修正，旧回执仍保留。

### 3. 组分名称准备和 OPSIN

`prepare_component` 必须包含 `raw_name`、`full_name`、`aliases`、来源和理由。Registry 只提供候选，不替代本文来源事实。

主 `resolve` 先解析 `full_name`。若状态是 `UNSUPPORTED` 或 `INVALID`，工具只读取本次准备回执中的 `raw_name` 和 `aliases`，逐一做真实 OPSIN 查询，并在回执中保存 `supplemental_results`。若请求带有本文已经保存的有限图，工具同时返回 `supplemental_graph_checks`。补充结果不是自动替换：只有明确的 `GRAPH_MATCH` 才能作为模型进一步采用的依据，且仍要保留原文写法、歧义、盐、电荷、同位素和立体信息。

结构图的作用是核对名称解析结果，不能反向从图臆造文献名称。分子式相同、同义词在 Registry 中存在、或某个别名能被 OPSIN 解析，都不能单独证明原文身份。

### 4. 命名和来源复核

模型根据本篇页面和工具回执选择候选名称，声明适用范围、规则理由、假设和未知。`review_naming` 是同一模型的来源和规则复核，`independent_review` 仍为 `NOT_REVIEWED`。`finalize` 要求主要对象的 identity/quantities 来源复核和当前图、名称、关系、性质绑定。

### 5. 正式发布

`finish` 只在候选无机械错误时生成 `READY_FOR_HOST_COMMIT`。宿主随后原子写入：

* `versions/<version>/bundle.json`：完整内容哈希绑定的不可变版本；
* `adopted/<source_sha256>.json`：当前来源采用指针；
* 任务 `sealed.json`：运行、候选和 completion 哈希。

一篇正常交付文献通常只有一个正式采用版本。若发生实质化学身份、结构、名称或来源范围修正，必须创建新版本并保留旧版本；不能覆盖旧 bundle，也不能把补充属性写回旧候选。

### 6. 发布后补充

OPSIN/RDKit 名称核验、PubChem 性质、页面索引和组分库自动更新属于补充层。名称核验按版本、材料哈希和图哈希单独生成回执；PubChem 写入性质缓存；这些动作不改变采用版本。阅读器只读这些回执，打开页面不会执行 OPSIN。

## 失败和重试规则

* `UNSUPPORTED`：工具覆盖不足，保留原名称和候选范围；不是化学错误。
* `MISMATCH`：名称解析图与保存图不一致，不能用分子式或删除立体来放行。
* `PARSER_GRAPH_BOUNDARY`：OPSIN 有输出，但现有有限图边界拒绝自由基/元素原子等表示；不标为通过。
* `MODEL_CAPACITY`：同一 session 在原截止时间内做有限恢复；仍失败则封存 `INCOMPLETE`，没有版本、没有采用指针、没有组分库记录。不能换模型冒充连续运行。
* 机械格式错误：在同一 session 修正并重新 finalize；不产生额外正式版本。

## 当前实证

18 篇封存文献的补充核验为 203 条 `GRAPH_MATCH`、2 条 `PREPARED_GRAPH_MATCH`、2 条 `PARSER_GRAPH_BOUNDARY`、2 条 `MISMATCH`，其余为无有限图或不适用范围；原始 189 条 resolve 回执仍没有被改写。

此前两篇修复任务均有正式采用版本，并分别产生真实 OPSIN 23 条和 1 条成功回执。最新真正未执行来源中，45 已交付并让组分库从 177 篇/4,253 条记录变为 178 篇/4,254 条记录；46 的两次独立尝试均因模型容量封存为 `INCOMPLETE`，没有被计入交付或入库。

## 可迁移到其他领域的最小方法

迁移到其他领域时保留五个接口：来源冻结、候选状态、来源绑定的名称准备、实际工具回执、不可变发布。只替换领域的来源观察器、结构/实体校验器和命名规则；不要把领域词典直接当事实，也不要把外部工具命中直接当最终身份。所有候选都要保留原始字面、规范化表达、证据范围、未知和回放哈希。

工程验证通过不等于科学准确率或独立化学审核。当前运行时仍是 Kernel `0.9.0`，优选 IUPAC/PIN 未认证。
