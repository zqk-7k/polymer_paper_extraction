## 当前实际执行流程

1. 宿主复制原始 PDF、记录 SHA-256，调用 MinerU，保留实际网络回执、版面块和直接 PDF 文本；页图独立保存。每篇的主会话读取全文、来源索引及页图，重要结构或冲突数字需要直接看图。解析、图像观察和人工参考是不同的证据来源。
2. 同一主会话整理主要材料、有限组分、组分使用实例、连接、投料与产物组成基准。原文名称、全称、缩写、同义词和商品名不简单拼成一个工具输入。`prepare_component` 保存原文对应关系、来源引用、系统重述理由、假设和歧义，并对已有 Registry 作有限候选查询。
3. `resolve` 必须绑定准备回执中的确切工具名称；新作业不允许跳过该准备环节。OPSIN 解析名称为图，RDKit 检查连接、盐、电荷、同位素、立构、端口及计算性质。工具失败保留原输入和实际失败，改变表达后再作有限重试。公共查询已有真实回执入口，只有实际调用才显示为执行；未调用的 PubChem 不算成功。
4. 图分别声明有限分子、重复单元、构成单元、单价残基或局部网络。全部通过同一个 `Kernel/create_passport/NamingService`。重复单元质量不是聚合物 Mn/Mw；去掉端口计元素不等于补氢封端。有限来源分子正确也不能自行证明实际聚合方式。
5. 主要材料明确选择名称路线，并使用 `identity-evidence-nomenclature/1.1` 声明原文支持、较宽范围或最可能假设。工具返回正式名称后，主会话采用该确切名称；数量和身份限定仍独立保存。假设必须有陈述、理由及本篇来源引用，保留其他可行情况，不能升级为原文事实。
6. 对最新状态执行名称/图/范围核对和 review，再 finish。新作业的主要材料不能只以材料描述交付，也不能以缺少工具或缺少验证冒充成功。宿主将完整候选、原文索引及实际工具回执封存、采用并哈希读回。三种阅读入口显示同一版本；旧版本可回放。

每篇使用一个持续的 gpt-6.1-sol/xhigh 会话和 workspace-write。预检实际验证文件读取、图像工具、域工具、写入和同一会话恢复。CLI 调用次数不等于服务端模型请求次数，后者没有暴露。故障后的新尝试必须单列原尝试、原截止时间、复用证据及新预算，不能重写旧失败记录。

## 已支持的命名路径及限制

| 路径 | 当前可执行范围 | 必须保留的限制 |
|---|---|---|
| 有限分子系统名 | OPSIN 名称与完整有限图一致，盐/电荷/同位素/已指定立构保留 | 图一致不是实物身份或 PIN 独立认证 |
| 来源型 poly、co、alt、net | 有限来源组分已核对；共聚/交替/网络关系有来源证据或明确假设 | 不能由名称推定未报告序列、转化率、网络拓扑 |
| 结构型理想重复构成 | 复用已有分解、周期键、声明 CRU 与图一致性检查；端基和链长未定不一概阻断 | 全部 RSSOP 优选规则、复杂分解和立构规则尚未完成 |
| 点改性 `[poly(A)]-mod-J` | 基础聚合物、来源组分和单价取代残基分别绑定，显式 OPSIN radical 模式检查残基 | 不适用于把聚合侧链或网络概括成点取代；位置/程度未知另列 |
| 来源型 graft | 骨架和聚合侧链来源有核对；聚合侧链关系有证据或最可能假设 | 不把无证据的分支长度、连接位置或接枝组成当事实 |
| blend | 各聚合组分已命名，物理共混关系及来源用量基准独立保留 | 不将投料份数自动改为产物组分，也不与接枝关系混淆 |
| 异构体选择 | 保存多个已核对的名称与图，可在明确最可能假设下选一个名称 | 不删除其他候选，不隐去位次/立构歧义 |

## 如何持续提高且控制规模

第一优先是消除执行摩擦：依据来源准备解析名称；由工具给出正式命名文本后再采用；减少同一个名称的重复失败。优先提取主要材料、决定连接的单体/前体、接枝或改性组分、用量基准及身份相关性质。测量耗材和一般性能保留来源用途即可，不将支持对象增多当成准确率提升。

第二优先是通用规则缺口。按真实失败类型建立新样例：来源/结构名称转换，盐和同位素，双键与残基端口，来源投料与产物组成，点改性与聚合接枝边界，以及异构体假设。正反例必须跨来源，不能用本次论文 ID、人工 JSON 或自建 expected 结构求解。开发生成的样例需要标为开发样例，不能自动变成独立审核 gold。

第三优先是理想重复构成的完整结构名与优选 CRU。逐步补齐有证据的子单元分解、连接方向、化学位次、立构和 RSSOP 的优先级/平局处理，保存每一步规则依据与整图回验；只有独立审核完成的部分才能扩展认证范围。来源型名可以先满足明确的化学内容，不能把它统计为图到结构名生成成功。

基础连接还存在边界：本应用复用了现有 Registry、Kernel、命名服务、RDKit、OPSIN 和公共查询入口，但并未将旧系统的整套 8,859 条组件库自动转换为当前可信求解能力。后续如需接入该库，应作只读、可追溯的有限候选适配，再核对结构和来源；不把目录 ID、公式或 expected 字段当名称/结构求解输出，不直接写共享数据库，不批量抓取 PoLyInfo。

持续评价应看同类对象的名称、图、连接、组成基准和保留未知有没有改善。新的对象数量、通过一次 pytest、OPSIN 能解析或自动 review 都不能单独证明科学完成。保留失败例子和撤回说明比添加综合分数更有用。

- [IUPAC modified polymer nomenclature, 2014](https://doi.org/10.1515/pac-2014-0610)：点改性与其他改性范围区分。
- [IUPAC source-based nomenclature, 2016](https://doi.org/10.1515/pac-2015-0702)：单链、接枝及相关来源型规则。
- [IUPAC RSSOP](https://iupac.qmul.ac.uk/rssop/)：规则有机聚合物结构型命名。
- [OPSIN](https://github.com/dan2097/opsin)：名称到结构解析；不等于逆向优选命名生成器。
